# 0004 — `tinyprobe init`

- **Status:** Draft
- **Roadmap:** M1-8
- **Repositories:** tinyprobe
- **PRs:** —

## Problem

The first minutes decide whether someone adopts tinyprobe. Today they read the guide's "Project layout", create the folders by hand, write an env file, remember the `.gitignore` lines, and paste a long prompt for their agent. Coding agents that open the repository later don't know tinyprobe is there: nothing tells them to run `tinyprobe guide` before touching the files, so they guess the syntax.

## Proposal

```text
$ tinyprobe init

  ⚡ tinyprobe 0.12.0

  + tinyprobe/api/
  + tinyprobe/workflows/
  + tinyprobe/env.example.yaml
  + tinyprobe/env.local.yaml        not committed: put real credentials here
  + .gitignore                      2 lines added
  + AGENTS.md                       section "API tests (tinyprobe)" added

  Next: ask your coding agent to write the tests:

    Run `tinyprobe guide` and follow it: look at this backend's routes, authentication and seed data,
    write the tinyprobe API file and workflows in tinyprobe/, then run them until they pass.
```

`tinyprobe init --base-url http://localhost:8080` puts that URL in the env files; without it, `baseUrl: http://localhost:8080`.

What it writes:

```yaml
# tinyprobe/env.example.yaml (and env.local.yaml)
# Values for the workflows: tinyprobe run tinyprobe/workflows -e tinyprobe/env.local.yaml
baseUrl: http://localhost:8080
```

```text
# .gitignore, appended
tinyprobe/env.*.yaml
!tinyprobe/env.example.yaml
```

```markdown
## API tests (tinyprobe)

The API tests are tinyprobe files in `tinyprobe/`: endpoints in `api/`, workflows in `workflows/`.
Before you write or change them, run `tinyprobe guide` and follow it. Check a file with
`tinyprobe inspect <file>`, and run the tests with `tinyprobe run tinyprobe/workflows -e tinyprobe/env.local.yaml`.
Credentials go only in `tinyprobe/env.local.yaml`, which is not committed.
```

Rules:

- **Never overwrites.** An existing file or folder is left as it is and shown with `=` ("exists, left as is"). In `.gitignore`, only missing lines are added. In `AGENTS.md`, the section is added only when the file does not already mention `tinyprobe guide`. Running `init` twice changes nothing the second time.
- **Where.** The current directory. `tinyprobe init <folder>` uses another one (the `tinyprobe/` folder and the root files go inside it).
- **Exit codes.** `0` when everything is in place (created or already there), `2` for invalid arguments or a file that cannot be written.
- No example endpoints or workflows: they would be fake. The agent writes them from the real backend.

## Validation

```text
Error: Cannot write tinyprobe/env.local.yaml: access denied.
Error: Unknown option '--base' for 'init'.
```

## Protocol

None: `init` has no JSON output.

## Extension

Optional, separate task: a "tinyprobe: Initialize" command that runs `tinyprobe init` in the workspace folder. Needs the CLI version that has `init`.

## Docs

- `README.md`: Quick start starts with `tinyprobe init`; the prompts of "Generate tests with a coding agent" stay as they are.
- `docs/llm-guide.md` section 2: "if `tinyprobe/` does not exist, run `tinyprobe init`".
- `--help` and the usage text.

## Out of scope

- Detecting the backend's port or framework to fill `baseUrl`.
- Writing agent-specific files beyond `AGENTS.md` (Claude Code skill, Cursor rules: M2-2).

## Acceptance criteria

- [ ] `tinyprobe init` creates the layout above in an empty repository, and a second run changes nothing.
- [ ] Existing files are never modified, except the lines appended to `.gitignore` and the section appended to `AGENTS.md`.
- [ ] `tinyprobe run tinyprobe/workflows -e tinyprobe/env.local.yaml` works right after `init` once a workflow exists (with M1-7).
- [ ] Unit tests in a temporary folder: empty folder, everything already there, partial `.gitignore`, `AGENTS.md` with and without the section.
- [ ] `scripts/dev.sh check` passes.

## Open questions

1. **Which instruction files?** Recommended: `AGENTS.md` always (read by Codex, Cursor, Copilot and others), and the same section in `CLAUDE.md` only if that file already exists. The alternative is to create both.
2. **Create `env.local.yaml` too?** Recommended: yes, so the run command works at once; it is ignored by git. The alternative is only `env.example.yaml`, and the user copies it.
3. **Print the agent prompt at the end?** Recommended: yes, the short one above; it is the next thing to do.
